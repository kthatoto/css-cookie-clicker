RULEBOOK

左は遊べる盤面。右はそれを動かしている CSS の全文です

左の 🍪 を押してみてください。右のルールのうち、いま条件に当てはまっているものだけが光ります。
光らせている判定も :has() です。ルールブック自体がルールブックの実演になっています。

STEP 1

押すと「数え上げのルール」が当たる

checkbox が checked になると .rate-1 > input:checked に当てはまり、そのルールの counter-increment が効きます。残高はこの積み上げの結果です。

STEP 2

5枚たまると「購入可能にするルール」が当たる

「5枚あるか」を数えているのではありません。5個目の checkbox が checked かどうかを形で見ているだけです。

STEP 3

買うと3本のルールが同時に当たる

減算・rate-1 の無効化・rate-2 の有効化。どれも #item1 が checked かどうかを見ているだけの、別々のルールです。

STEP 4

rate-2 で押すと、別の数え上げルールが当たる

rate-1 のルールも光ったままです。過去に押した分は rate-1 のルールで数えられ続けるので、後から2倍にはなりません。

STEP 5

光る条件は、すべて先に書いてあります

右のルールはゲーム中に増えも減りもしません。最初から全部そこにあって、当たるものが入れ替わっているだけです。

STEP 6

だからルールは「押し方の組み合わせ」の数だけ要る

下はどれも合計10枚になる押し方。CSS から見るとまったく別の状態なので、1通りにつき1本ルールが必要です。

STEP 7 ／ ネタバラシ

CSSは計算していない。全部あらかじめ書いてある

JavaScript なら数行で済むものが、CSS では起こりうる状態の数だけ並ぶ。これがこのゲームの構造そのものです。

アイテムが4個なら、購入済みの組み合わせ16通り × この押し方の組み合わせ。 だから style.css は 24,000行以上になります。

手続き的（JavaScript なら）

// 状態は変数。押されたら「計算して」求める
let cookies = 0, rate = 1;

onClick = () => cookies += rate;
onBuy   = (item) => {
  cookies -= item.price;
  rate += 1;
};

この数行で、あらゆる残高に対応できる。実行時に計算するから。

宣言的（このゲームのCSS）

/* 「この状態のときはこう見える」を並べるだけ */
#main:has(#item1:checked)
     :has(> .rate-1 > input:nth-last-child(6):checked)
  .item2 .purchase { background: skyblue; }

/* ↑ これが起こりうる状態の数だけ並んでいる */

CSSに「足す」も「比べる」もない。あるのは「この形に当てはまるか」だけ。

だから残高は「増えていく数」ではなく、今この瞬間の checked の並びから毎回そのまま読み出されている結果です。 そしてこの資料のページ送りも同じ仕掛けで、JavaScript は1行もありません。

  • 🍪 checkbox 1個 ＝「1回押した」という記憶。持てる情報はこれだけ。
  • 🔢 残高は counter が数え上げた結果。過去の分の単価は後から変わらない。
  • 🧩 購入可否も rate 切替も、:has() で形を見ているだけ。
  • 🧨 ルールは実行中に増えない。最初から全部そこにある。
  • 🛠 だから Sass が状態空間を総当たりして生成する。24,000行以上のCSSはその結果。
