STEP 1

checkbox 1個 ＝ クリック1回分の記憶

このゲームに変数はありません。あるのは checked か unchecked かの2状態だけ。
左の 🍪 は <label>、隣が <input type="checkbox"> 本体。同じ1個の要素なので、cookie を押すと本物のチェックが入ります。

unchecked
まだ押されていない
checked
「1回押した」という事実だけが残る

押しても「1回押された」以上のことは記録されません。何枚もらえるかは、このあと CSS 側が決めます。

STEP 2

同じ場所に重ねると「連続クリック」になる

本物は同じ座標に 100個重なっています。後に書いた要素ほど手前に描かれるので、押せるのはいつも一番手前の1個だけ。押されたものは脇へ飛び、次が手前に出てきます。

↑ 下の列が本物の <input type="checkbox"> 6個（表示専用）。🍪を押すと右端から順に ✓ が入ります。

z-index は使っていません。「後に書いた要素が手前」という既定の規則だけです。

STEP 6

同じ10枚でも、押し方ごとに別のCSSが要る

どれも合計10枚になる押し方ですが、CSSから見るとまったく別の状態。「10枚あるか」を計算する手段がないので、押し方の組み合わせ1通りにつき、セレクタが1本ずつ用意されています。

1枚 × 10回＝10枚 → item2（10枚）が買える
/* 1枚 × 10回 ＝ 10枚 */
#main:has(#item1:checked):has(#item2:not(:checked))
     :has(> .click-group.rate-1 > input:nth-last-child(10):checked)  /* ← 1枚の群を10回 */
  .item2 .purchase { --purchase-background: skyblue; }
1枚 × 8回＋2枚 × 1回＝10枚 → item2（10枚）が買える
/* 1枚 × 8回 ＋ 2枚 × 1回 ＝ 10枚 */
#main:has(#item1:checked):has(#item2:not(:checked))
     :has(> .click-group.rate-1 > input:nth-last-child(8):checked)  /* ← 1枚の群を8回 */
     :has(> .click-group.rate-2 > input:nth-last-child(1):checked)  /* ← 2枚の群を1回 */
  .item2 .purchase { --purchase-background: skyblue; }
1枚 × 6回＋2枚 × 2回＝10枚 → item2（10枚）が買える
/* 1枚 × 6回 ＋ 2枚 × 2回 ＝ 10枚 */
#main:has(#item1:checked):has(#item2:not(:checked))
     :has(> .click-group.rate-1 > input:nth-last-child(6):checked)  /* ← 1枚の群を6回 */
     :has(> .click-group.rate-2 > input:nth-last-child(2):checked)  /* ← 2枚の群を2回 */
  .item2 .purchase { --purchase-background: skyblue; }
1枚 × 2回＋2枚 × 4回＝10枚 → item2（10枚）が買える
/* 1枚 × 2回 ＋ 2枚 × 4回 ＝ 10枚 */
#main:has(#item1:checked):has(#item2:not(:checked))
     :has(> .click-group.rate-1 > input:nth-last-child(2):checked)  /* ← 1枚の群を2回 */
     :has(> .click-group.rate-2 > input:nth-last-child(4):checked)  /* ← 2枚の群を4回 */
  .item2 .purchase { --purchase-background: skyblue; }

補足：:nth-last-child(8):checked は「後ろから8番目が checked」＝ 8回以上押したという意味。重ねた checkbox は後ろから順に消費されるので、そこからさらに押しても条件は成立したまま ＝ 一度買えるようになったら、追加でクリックしても買えるままです。

STEP 8

CSSは計算していない。全部あらかじめ書いてある

手続き的（JavaScript なら）

// 状態は変数。押されたら「計算して」求める
let cookies = 0, rate = 1;

onClick  = () => cookies += rate;
onBuy    = (item) => {
  cookies -= item.price;
  rate += 1;
};

この数行で、あらゆる残高・あらゆる購入状況に対応できる。実行時に計算するから。

宣言的（このゲームのCSS）

/* 「この状態のときは、こう見える」を並べるだけ */
#main:has(#item1:checked)
     :has(> .rate-1 > input:nth-last-child(6):checked)
     :has(> .rate-2 > input:nth-last-child(2):checked)
  .item2 .purchase { background: skyblue; }

/* ↑ これが、起こりうる状態の数だけ並んでいる */

CSSに「足す」も「比べる」もない。あるのは「この形に当てはまるか」だけ。

だから残高は「増えていく数」ではなく、今この瞬間の checked の並びから、毎回そのまま読み出されている結果にすぎません。

STEP 9

この量は手で書けない。だから Sass で全列挙する

書いたもの：再帰mixin（抜粋）

@mixin buyable-frontier(
  $base, $item, $required, $max-rate,
  $counts: (), $rate: 1, $earned: 0
) {
  @if $earned >= $required {
    /* ちょうど買える境界にだけルールを出力 */
    #{$base}#{click-conditions($counts)} … {
      --purchase-background: skyblue;
    }
  } @else if $rate <= $max-rate {
    @for $clicks from 0 through $remaining {
      /* 各rateの押した回数を総当たり */
      @include buyable-frontier(…, $rate + 1,
        $earned + $clicks * $rate);
    }
  }
}
