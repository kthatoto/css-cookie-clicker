INTRO

CSS Cookie Clicker のしくみを「触って」理解する

このゲームは JavaScript を一切使わず、HTML の checkbox と CSS の :checked / :has() / counter() だけで動いています。

このスライドの使い方

  • スライド内に埋め込まれた ミニデモ（checkbox）は実際にクリックして操作してください。JSは一切使っていません。
  • ページの送り／戻し／リセットだけは、発表向けの補助として最小限の JavaScript を使っています。
  • 下部のボタンまたは矢印キー / Space で進み、いつでも R キー（またはリセットボタン）で最初の状態に戻せます。

Tip: 気になったら戻って何度でも触ってみてください。状態は各スライドごとに独立しています。

STEP 1

checkbox 1個 ＝ クリック1回分の「記憶」

本物のゲームでは、クッキーを1回クリックするたびに input[type=checkbox] が1個「チェック済み」に変わります。チェック状態はそのまま DOM 上に記録され続けます。

まだクリックされていません（unchecked）。 クリック済みです。:checked が有効になりました。

CSSの実体（抜粋）

#cookie:checked { left: 500px; }

実際のゲームではクリックすると checkbox が横へ吹き飛び、見えなくなります（＝消費済みの印）。

STEP 2

100個（ここでは6個）を重ねて、手前から1個ずつ消費する

本物のゲームは同じ場所に checkbox が100個ぴったり重なっています。CSSは「後の DOM 要素ほど手前に描く」ので、押せるのは常に一番手前のまだ押していないもの。押すと脇へどき、1つ前の checkbox が新たに手前に出てきます。

合計: クリック

クリックしてみてください。数字は CSS counter だけで増えます。

CSSの実体（抜粋）

.click-group.rate-1 > input:checked { counter-increment: cookies 1; }

z-index は使っていません。DOM順が後ろの要素ほど手前に描かれるという通常の規則だけを利用しています。

STEP 3

「買えるかどうか」も :has() で判定する

価格5のアイテムの例です。左のスタックを5回チェックすると合計5枚になり、購入ボタンが初めて押せる状態（水色）に変わります。

所持: 枚

まだ5枚集まっていないため購入できません。5枚たまったので購入できます！押すと5枚引かれます。購入済みです。5枚引かれました。

CSSの実体（抜粋）

.shop:has(#click5:checked) .buy { background: skyblue; cursor: pointer; }

実際は「購入済みアイテム × 各rate群のクリック数」の全組み合わせに対して、Sassがこの手のルールを大量生成しています（後述）。

STEP 4

1プレイぶんを触ってみる：10回クリック → 購入 → rate-2 で1回

rate-1 群を 10回クリックして 10枚 → item1（5枚）を購入して 5枚 → 切り替わった rate-2 群を 1回クリックして 7枚。下の数字も点灯も、すべて CSS counter と :has() の結果です。

rate-1 群（1クリック＝1枚・重ねた10個）
rate-2 群（1クリック＝2枚・購入後に有効）

所持: 枚

0枚開始 10枚rate-1 ×10 5枚item1 購入 −5 7枚rate-2 ×1（+2）

rate-1 群は購入後に隠れますが、DOM からは消えません。だからそれまでに積んだ10枚ぶんは ×1 のままカウントに残り続けます。

CSSの実体（抜粋）

.click-group.rate-1 > input:checked { counter-increment: cookies 1; } .click-group.rate-2 > input:checked { counter-increment: cookies 2; } #item1:checked { counter-increment: cookies -5; } #main:has(#item1:checked) .click-group.rate-1 { visibility: hidden; } #main:has(#item1:checked) .click-group.rate-2 { visibility: visible; }

rate が上がっても、過去のクリックは rate-1 群の checkbox として残ったままなので遡って2倍にはなりません。だから 10 + (−5) + 2 = 7 になります。

STEP 5

状態遷移図とミニデモを連動させる

同じ「購入済みチェック」の状態を、下の状態遷移図のハイライトにもそのまま反映しています。

購入前
rate-1 が有効
→
item1 購入後
rate-2 が有効

チェックのON/OFFに合わせて、今どちらの状態にいるかがそのままハイライトされます（:has() のみで実装）。

STEP 6

「状態」とは購入済みアイテムの集合そのもの

item A・item B を好きな順番でチェックしてみてください。どちらを先に買っても、最終的にハイライトされる箱（＝状態）は同じです。

{ }
{A}
{B}
{A, B}

A→B の順でも B→A の順でも、両方チェックすれば必ず {A, B} がハイライトされます。

CSSの実体（考え方）

:has(#a:checked):has(#b:checked) .set-ab { /* 強調表示 */ }

実ゲームでは、購入可能かどうかの判定もこの「集合」に対して行われます。アイテムが増えるほど、判定すべき集合の数は 2 の累乗で増えます。

STEP 7

Sassは「状態空間を総当たりして生成するコンパイラ」

購入可否や rate切替のCSSは手書きではありません。購入済み集合 × 各rate群のクリック数 の全組み合わせを Sass の再帰mixinで列挙し、購入可能な境界にだけスタイルを当てるCSSルールを事前生成しています。

組み合わせが爆発する理由

  • 購入済みアイテムの集合が 2^N 通り
  • 各集合ごとに、有効な rate群のクリック数パターンがある
  • その全組み合わせの「境界」にだけ購入可能スタイルを生成

アイテムを増やす設計変更は、CSSの生成量に対して非常にコストが高いことがわかります。

SUMMARY

まとめ

  • JavaScript は一切使わず、input:checked + CSS counter() + :has() だけでゲームが成立している。
  • checkbox 1個 ＝ クリック1回分の記憶。過去に積んだ分の rate は後から変わらない。
  • 購入可否・rate切替・状態遷移図のハイライトは、すべて祖先要素に対する :has() による条件分岐で表現できる。
  • 「状態」とは購入済みアイテムの集合そのもの。購入順序は関係ない。
  • Sassは、この状態空間を総当たりして境界のCSSだけを事前生成するコンパイラとして働いている。アイテムが増えると組み合わせは指数的に増える。

R キー、または下のリセットボタンで、すべてのミニデモをチェック無しの状態に戻して最初からもう一度試せます。
