RULEBOOK

左は遊べる盤面。右はそれを動かしている CSS の全文です

左の 🍪 を押してみてください。右のルールのうち、いま条件に当てはまっているものだけが光ります。
ルールや盤面にマウスを乗せると、対応する相手が青くフォーカスされます。

STEP 1

押すと「数え上げのルール」が当たる

checked になった input が counter-increment: cookies 1 ＝「カウンタに1足す」の対象になります。残高はその積み上げを毎回読み出した結果です。

STEP 2

5枚たまると「購入可能にするルール」が当たる

「5枚あるか」を数えてはいません。後ろから5番目の checkbox が checked かを見ているだけ。これは「5回以上押した」の意味なので、さらに押しても買えるままです。

STEP 3

買うと3本のルールが同時に当たる

購入もただの checkbox（ボタンの隣が実体）。減算・rate-1の無効化・rate-2の有効化、どれも #item1 が checked かを見ているだけの別々のルールです。

STEP 4

rate-2 で押すと、別の数え上げルールが当たる

rate-1 のルールも光ったまま。過去に押した分は rate-1 のルールで数えられ続けるので、後から2倍にはなりません。

STEP 5

ルールと盤面は、つながっています

右のルールにマウスを乗せてみてください。作用先のカードと、checked の対象が青く光ります。逆にカードに乗せると、対応するルールが光ります。この判定も全部 :has() です。

STEP 6

ルールは「押し方の組み合わせ」の数だけ要る

下はどれも合計10枚になる押し方。CSSから見るとまったく別の状態なので、1通りにつき1本ルールが必要です。

STEP 7

CSSは計算していない。全部あらかじめ書いてある

JavaScript なら数行で済むものが、CSSでは起こりうる状態の数だけ並ぶ。これがこのゲームの構造そのものです。

ネタバラシ

この資料には、JavaScript が1行もありません

いままでのページ送りも、ゲームとまったく同じ仕掛けで動いていました。

rate-1 の群（1回 ＝ +1枚）

↑ 本物の checkbox 8個（表示専用）。🍪から右端の順に ✓。
input:checked → counter-increment: cookies 1

ショップ ／ item1・5枚

#item1:checked → counter-increment: cookies -5

rate-2 の群（1回 ＝ +2枚・購入後に有効）

↑ こちらは別の checkbox 群。
input:checked → counter-increment: cookies 2
残高枚
counter-increment ＝「カウンタに足す」宣言。checked の数だけ積み上がった結果を毎回読み出しています。
#result::after → content: counter(cookies) "枚"
このゲームを動かしている CSS ルール（全文・増減しません）。マウスを乗せると作用先が光ります。
当たっている.click-group.rate-1 > input:checked { counter-increment: cookies 1; /* checked 1個につき +1 */ }
当たっている.click-group.rate-2 > input:checked { counter-increment: cookies 2; /* checked 1個につき +2 */ }
当たっている#main:has(> .rate-1 > input:nth-last-child(5):checked) :not(:has(#item1:checked)) .item1 .purchase { --purchase-background: skyblue; /* 5回以上押した＝買える */ }
当たっている#item1:checked { counter-increment: cookies -5; /* 価格ぶんの減算 */ }
当たっている#main:has(#item1:checked) .click-group.rate-1 { visibility: hidden; pointer-events: none; }
当たっている#main:has(#item1:checked) .click-group.rate-2 { visibility: visible; pointer-events: auto; }
当たっている#result::after { content: counter(cookies) "枚"; /* 積み上げの読み出し */ }
1枚 × 10回＝10枚
/* 1枚 × 10回 ＝ 10枚 */
#main:has(#item1:checked):has(#item2:not(:checked))
     :has(> .rate-1 > input:nth-last-child(10):checked)  /* ← 1枚の群を10回 */
  .item2 .purchase { --purchase-background: skyblue; }
1枚 × 8回＋2枚 × 1回＝10枚
/* 1枚 × 8回 ＋ 2枚 × 1回 ＝ 10枚 */
#main:has(#item1:checked):has(#item2:not(:checked))
     :has(> .rate-1 > input:nth-last-child(8):checked)  /* ← 1枚の群を8回 */
     :has(> .rate-2 > input:nth-last-child(1):checked)  /* ← 2枚の群を1回 */
  .item2 .purchase { --purchase-background: skyblue; }
1枚 × 6回＋2枚 × 2回＝10枚
/* 1枚 × 6回 ＋ 2枚 × 2回 ＝ 10枚 */
#main:has(#item1:checked):has(#item2:not(:checked))
     :has(> .rate-1 > input:nth-last-child(6):checked)  /* ← 1枚の群を6回 */
     :has(> .rate-2 > input:nth-last-child(2):checked)  /* ← 2枚の群を2回 */
  .item2 .purchase { --purchase-background: skyblue; }
1枚 × 2回＋2枚 × 4回＝10枚
/* 1枚 × 2回 ＋ 2枚 × 4回 ＝ 10枚 */
#main:has(#item1:checked):has(#item2:not(:checked))
     :has(> .rate-1 > input:nth-last-child(2):checked)  /* ← 1枚の群を2回 */
     :has(> .rate-2 > input:nth-last-child(4):checked)  /* ← 2枚の群を4回 */
  .item2 .purchase { --purchase-background: skyblue; }

補足：:nth-last-child(N):checked は「N回以上押した」の意味。追加でクリックしても条件は成立し続ける ＝ 一度買えたら買えるまま。 アイテム4個なら購入済みの組み合わせ16通り × この押し方の組み合わせで、style.css は 24,307行になります。

手続き的（JavaScript なら）

// 状態は変数。押されたら「計算して」求める
let cookies = 0, rate = 1;

onClick = () => cookies += rate;
onBuy   = (item) => {
  cookies -= item.price;
  rate += 1;
};

この数行で、あらゆる残高に対応できる。実行時に計算するから。

宣言的（このゲームのCSS）

/* 「この状態のときはこう見える」を並べるだけ */
#main:has(#item1:checked)
     :has(> .rate-1 > input:nth-last-child(6):checked)
  .item2 .purchase { background: skyblue; }

/* ↑ 起こりうる状態の数だけ並んでいる */

CSSに「足す」も「比べる」もない。あるのは「この形に当てはまるか」だけ。

だから残高は「増えていく数」ではなく、今この瞬間の checked の並びから毎回そのまま読み出されている結果です。

…ところで、まだひとつだけ話していないことがあります →

  • 🍪 checkbox 1個 ＝「1回押した」という記憶。持てる情報はこれだけ。
  • 🔢 残高は counter が数え上げた結果。過去の分の単価は後から変わらない。
  • 🧩 購入可否も rate 切替も、:has() で形を見ているだけ。
  • 🧨 ルールは実行中に増えない。最初から全部そこにある。
  • 🛠 だから Sass が状態空間を総当たりして生成する。24,307行のCSSはその結果。
  • ページ送り → <input type="radio" name="step"> 10個
  • ← → キー → ラジオグループの標準動作（CSSでもJSでもなくHTMLの仕様）
  • リセット → <input type="reset">（formの標準機能）
  • パネルやルールの点灯 → すべて :checked と :has()
/* この資料のページ送り（実物・これが全部） */
#st10:checked ~ .stage .p-reveal {
  opacity: 1;
  visibility: visible;
}
/* × スライドの枚数ぶん */
